# Regex: a regular-expression engine as a Loimi vm, shipped as a C library

This example is a regular-expression library for C, written in Loimi.
This document is for C programmers who use the library and for readers
who want to see how it is built.

A pattern compiles to bytecode for the `Rx` vm (`vm.lm`). Two engines
can run that bytecode:

- a backtracking matcher, which is the vm's handlers;
- a Pike VM (`pike.lm`), which runs in linear time. It is host code that
  uses the decoders the vm generates.

Both give the results of Python's `re` on bytes, captures included.

## Building

```sh
./target/release/loimi build examples/regex/lib.lm --lib -o librx.a --header rx.h
```

Use `--shared` instead of `--lib` for a shared library. The library does
not use the garbage collector; it allocates with `std.mem` only.

## Syntax

| Element | Syntax |
|---|---|
| Literals | Any byte; `\` before punctuation; `\n \t \r \f \v \0` |
| `.` | Any byte except `\n` |
| Classes | `[abc]`, `[a-z]`, `[^...]`, with escapes and `\d \w \s` inside. `]` first is a literal, and so is `-` first or last. |
| Shorthands | `\d \w \s \D \W \S` (ASCII, as for Python bytes patterns) |
| Anchors | `^` (start of input), `$` (end of input, or before a final `\n`) |
| Groups | `( )` capturing, `(?: )` non-capturing |
| Alternation | `\|` |
| Quantifiers | `* + ? {m} {m,} {,n} {m,n}`, and lazy `*? +? ?? {m,n}?`. Counts go up to 1000. A `{` that does not start a valid quantifier is a literal, as in Python. |

These are not supported, and give a compile error:

- flags, and `(?...)` groups other than `(?:`;
- backreferences;
- lookahead and lookbehind;
- `\b \B \A \Z`;
- octal escapes other than `\0`;
- possessive quantifiers;
- Unicode.

Limits: 256K code words per pattern, and 40 nested loops whose body can
match the empty string.

**Matching** follows Python's `sre` exactly. That includes its rule for
loops whose body can match the empty string: an optional iteration
starts only if the previous optional iteration consumed input. So
`(a|)+` on `aa` gives group 1 = `(2, 2)`.

## C API

The header `rx.h` is generated by the build:

```c
#define RX_SEARCH 1u
#define RX_PIKE 2u
rx_regex *rx_compile(const void *pat, uint64_t len);  /* NULL only on an internal error; check rx_ok */
bool rx_ok(rx_regex *r);
loimi_str rx_error(rx_regex *r);                 /* "" if none; valid until the next call on r */
int64_t rx_error_offset(rx_regex *r);            /* byte offset in the pattern, or -1 */
uint32_t rx_groups(rx_regex *r);
int32_t rx_exec(rx_regex *r, const void *buf, uint64_t len, uint64_t start, uint32_t flags,
                int64_t *spans, uint64_t nspans);
void rx_set_step_limit(rx_regex *r, int64_t n);  /* 0: none */
loimi_str rx_disasm(rx_regex *r, uint32_t flags);
loimi_str rx_internal_error(void);               /* the last caught panic on this thread */
void rx_free(rx_regex *r);
```

### `rx_exec`

| Flag | Meaning |
|---|---|
| `RX_SEARCH` | Search, like `pattern.search(s, start)`. Without it, an anchored match, like `pattern.match(s, start)`. |
| `RX_PIKE` | Use the Pike VM instead of the backtracker. |

| Return value | Meaning |
|---|---|
| 1 | A match. |
| 0 | No match. |
| -1 | An error; see `rx_error`. The pattern did not compile, the backtracker hit its limit of 4M records, or the step limit was reached. |
| -2 | An internal error: a panic inside the library was caught; see `rx_internal_error`. Only `rx_free` is safe after it. |

On a match, `rx_exec` writes up to `nspans` (start, end) pairs to
`spans`: group 0, then each group in order. A group that did not take
part in the match gets -1.

### Ownership and threads

- The pattern and the subject are borrowed for the call. The library
  keeps no pointer into them.
- `spans` belongs to the caller.
- Strings returned by `rx_error` and `rx_disasm` belong to the regex.
- A regex holds its own scratch space for matching, so use each one from
  one thread at a time. Different regexes can run in parallel.

## How it works

### Bytecode

The bytecode is declared as `encoding fixed(u32)`, with these formats:

```
N  {op}
A  {op, a: 24}
J  {op, sj: s24}
AJ {op, a: 8, sj: s16}
```

The verifier checks each operand by its kind:

| Kind | Must be |
|---|---|
| `byte` | Below 256. |
| `cls` | An index into the class table. |
| `lit` | An index into the literal table. |
| `slot` | A capture slot. |
| `mark` | A loop mark. |
| `label` | An instruction boundary. |

| Op | What it does |
|---|---|
| `CHAR c` | Consumes the byte `c`. |
| `ANY` | Consumes any byte except `\n`. |
| `CLASS s` | Consumes a byte of a class. |
| `LIT l` | Consumes a literal string. |
| `CSTAR s`, `CPLUS s` | Greedy `[class]*` or `[class]+`, with one pair of backtrack records for the whole run. Backtracker only. |
| `BOL`, `EOL` | `^` and `$`. |
| `SAVE s` | Sets a capture slot to the current position. Undone on backtracking. |
| `SPLIT t` | Forks, trying the next instruction first. |
| `SPLITX t` | Forks, trying `t` first. |
| `JMP t` | Jumps. |
| `MARK m`, `UNMARK m`, `LOOP m t`, `NOPROG m t` | Implement the rule for loops that can match empty (see Matching above). |
| `MATCH` | Succeeds. |

The compiler emits two programs per pattern, and both are verified
before use:

- one for the backtracker, with `LIT`, `CSTAR`, `CPLUS` and
  superinstructions;
- one for the Pike VM, with single-byte steps.

The superinstructions were picked with `--vm-stats` on the benchmarks
(`stats.lm`): `SAVE_SPLIT_CPLUS_LIT`, `SAVE_CPLUS`, `SAVE_MATCH` and
`SPLIT_LIT`. A `budget` instrumentation variant of the vm counts
instructions for `rx_set_step_limit`.

### Files

| File | Contents |
|---|---|
| `syntax.lm` | The parser: pattern to tree. |
| `compile.lm` | Tree to bytecode (with `std.bc` labels), the first-byte set and the required byte. |
| `vm.lm` | The `Rx` vm: backtracking handlers, superinstructions, the step-limit variant. |
| `pike.lm` | The Pike VM. |
| `lib.lm` | The C API. |
| `host.c` | A C host with the commands `demo`, `test CASES`, `fuzz N SEED` and `bench`. |
| `fuzz.lm` | Mutates compiled code and runs what the verifier accepts on both engines. |
| `verify_test.lm` | Unit tests (`loimi test`): the verifier on hand-made bad programs, and the API in-process. |
| `stats.lm` | Benchmark driver for `--vm-stats`. |
| `bench.py` | The benchmarks run with Python's `re`. |
| `tests/gen.py`, `tests/cases.txt`, `tests/compare.py` | Differential tests against Python. |
| `check.sh` | Builds and runs all the checks below. |
| `dispatch.sh` | Tests and benchmarks in all three dispatch modes. |

## Testing and benchmarks

`check.sh` builds the library and the C host, then runs the demo, the
bytecode fuzzer, the verifier unit tests, a fuzz test on random byte
patterns (both engines must agree), and both engines against Python's
`re`.

```sh
examples/regex/check.sh                          # 2000 random cases, seed 1
examples/regex/check.sh --random 5000 --seed 3
examples/regex/check.sh --asan                   # build with AddressSanitizer
examples/regex/check.sh --fast                   # 2000 fuzz runs instead of 20000
```

To benchmark against PCRE2 and Python's `re`, after `check.sh` has built
`examples/regex/build`:

```sh
clang-19 -O2 -DHAVE_PCRE2 -Iexamples/regex/build examples/regex/host.c \
    examples/regex/build/librx.a -lpcre2-8 -o rxbench && ./rxbench bench
python3 examples/regex/bench.py
```
